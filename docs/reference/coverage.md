# Coverage

pogi emulates the services below. Each row says what a service does today and what it does not do yet. Every service is tested with the official SDK for its cloud.
Terraform (hashicorp/aws 6.x, google and azurerm) and the CDK CLI also run against pogi in
[`scripts/conformance.sh`](../../scripts/conformance.sh).

Each service has a depth:

- **Deep:** real behavior, plus links to other services. A queue can trigger a function, for example.
- **Core:** the main API, with real behavior.
- **Thin:** pogi stores your resources and reads them back, but nothing runs behind them. That is enough for tools such as Terraform.

ARNs (the IDs AWS gives resources) use the right prefix for the region: `aws`, `aws-cn` for China, and `aws-us-gov` for GovCloud.
The Terraform run also passes with `REGION=us-gov-west-1` and `REGION=cn-north-1`.

Names that end in `.localhost` (virtual-host S3, `execute-api`, `lambda-url`) resolve on macOS and on most Linux systems.
They don't resolve in Alpine Linux containers, which use a small C library without that rule. `pogi doctor` tells you which case you are in.

pogi covers 355 services: 144 AWS (88 with real behavior, 56 Thin), 108 Google Cloud (25 with real behavior, 83 Thin) and 103 Azure (29 with real behavior, 74 Thin). Each service is followed by its service id, the name `pogi services` prints. A product counts once, however many service ids it has: see [How services are counted](#how-services-are-counted).
